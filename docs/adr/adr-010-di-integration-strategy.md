# ADR-010: Dependency Injection Integration Strategy

## Status
Accepted

## Date
2026-08-13

**Status**: Accepted
**Date**: 2026-08-13 (Updated 2026-08-15, Corrected 2026-08-25)
**Deciders**: EricksonLopez.Mapper Architecture Team

## Context

Most enterprise .NET applications use `Microsoft.Extensions.DependencyInjection`. A mapping library should provide frictionless DI registration without forcing a hard dependency on DI abstractions into the core runtime package — which would introduce unnecessary baggage into lightweight microservices, console utilities, and trimmed AOT environments.

## Decision

1. **Assembly-Attribute Driven Discovery**:
   - DI integration is optional and triggered at compile time when `[assembly: GenerateMapperRegistration]` is present in the consuming assembly.
   - The Roslyn generator discovers this attribute via `context.SyntaxProvider.ForAttributeWithMetadataName("EricksonLopez.Mapper.GenerateMapperRegistrationAttribute", ...)` ensuring $O(1)$ incremental caching efficiency.

2. **Generated Extension Method**:
   - The generator produces `AddGeneratedMappers(this IServiceCollection services)` inside namespace `EricksonLopez.Mapper`:
     ```csharp
     // <auto-generated/>
     #nullable enable
     using Microsoft.Extensions.DependencyInjection;

     namespace EricksonLopez.Mapper
     {
         public static class MapperServiceCollectionExtensions
         {
             public static IServiceCollection AddGeneratedMappers(this IServiceCollection services)
             {
                 services.AddSingleton<global::Namespace.UserMapper>();
                 services.AddSingleton<global::Namespace.OrderMapper>();
                 return services;
             }
         }
     }
     ```
   - Custom converters referenced via `[UseConverter(Type)]` are additionally registered as `Transient` alongside the mapper Singletons.
3. **Singleton Lifetime**:
   - All generated mapper instances are registered as `Singleton` because generated mappers are pure, stateless, and thread-safe.
   - Static mappers (`public static partial class`) are omitted from registration since they do not require instantiation.

## Consequences

### Positive
- One-line DI registration in ASP.NET Core `Program.cs`: `builder.Services.AddGeneratedMappers()`.
- Zero core package dependency on DI libraries.
- $O(1)$ incremental pipeline caching for assembly-level discovery.

### Negative
- Consumers must supply `[assembly: GenerateMapperRegistration]` in their assembly to trigger the extension method generation.
