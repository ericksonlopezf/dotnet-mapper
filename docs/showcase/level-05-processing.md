## 1. Pure and Stateless Architecture

Mappers generated by `EricksonLopez.Mapper` maintain zero mutable internal state, zero instance variables, and zero static reflection caches. Every generated method behaves as a **pure function**:
- Immune to race conditions.
- Requires zero locking or synchronization primitives (`lock`, `Monitor`, `SemaphoreSlim`).
- Can be safely registered as a `Singleton` in IoC containers or invoked via static methods.

---

## 2. Concurrent Batch Processing with PLINQ

For high-throughput workloads or bulk data streaming (ETL, event ingestion):

```csharp
[Mapper]
public partial class BatchMapper
{
    public partial OrderRecordDto Map(OrderRecordEntity source);
}

// In the batch processing pipeline:
var mapper = new BatchMapper();
var orders = FetchLargeOrderBatch(100_000);

// Concurrent mapping across CPU cores:
var dtos = orders
    .AsParallel()
    .WithDegreeOfParallelism(Environment.ProcessorCount)
    .Select(mapper.Map)
    .ToList();
```

---

## 3. Integration with Asynchronous Channels (`System.Threading.Channels`)

Because mapping operations are synchronous and zero-allocation, they integrate cleanly into `ChannelReader<T>` streaming pipelines:

```csharp
await foreach (var entity in channelReader.ReadAllAsync(cancellationToken))
{
    var dto = mapper.Map(entity);
    await ProcessDtoAsync(dto, cancellationToken);
}
```

---

## 4. Architectural Boundaries

> [!NOTE]
> The library contains no built-in message queues or background worker threads. Its architectural scope is strictly focused on providing the fastest possible in-memory object transformation, delegating asynchronous scheduling and parallel orchestration to native .NET primitives (`Task`, `Channel`, PLINQ, or Background Services).
